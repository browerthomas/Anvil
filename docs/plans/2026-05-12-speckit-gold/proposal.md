# speckit-gold — proposal

> Lift the ideas from GitHub's spec-kit (96k★) that anvil is genuinely missing. v1 of this plan focuses on the four that survived adversarial review; `/clarify` deferred (see "Out of scope" below).

**Status:** draft
**Author:** tb
**Date:** 2026-05-12
**Plan ID:** speckit-gold
**Layout:** folder

---

## Goal

Four additive features land in anvil that close the real gaps between anvil and spec-kit: a **constitution** artifact that every dispatched agent reads, a **2-layer template override** so projects can customise without forking, **per-slice checklists** threaded through `/pre-merge-gate`, and an **/analyze-plan** file-existence consistency gate. A fifth idea (separating interrogation from specification) is deferred — adversarial review surfaced that operators get the same outcome from a `--save-transcript` flag on `/spec` without a new skill surface.

---

## Why now

- Spec-kit just crossed 96k★ on the same core loop anvil targets; the operator has flagged its constitution + template-override + checklist + analyze ideas as load-bearing upstream of anvil's strongest surface (the execution loop).
- Anvil's strength is the back half (`/grind`, `/codex-review`, `/dual-review`, `/pre-merge-gate`, `/auto-merge`, event log, plan-health). Front half (intent → locked plan) is comparatively thin. These four additions close that gap without churning the back half.
- Templates already live under `templates/` but are read from a fixed path with no override layer. Adopting projects can't customise without forking the repo. This bites OSS reach.
- Dispatched agents currently rediscover project rules per-slice. A unified constitution.md pinned into every brief closes that leak.
- Plans can drift from code state between writing and execution; `/analyze-plan` catches the cheapest class of drift (file paths cited in the plan that no longer exist) before `/grind` dispatches.

## Scope

### In scope

- New artifact: `.anvil/constitution.md` (project-local, operator-authored or scaffolded from template, prepended into every `dispatch-slice` brief). NOT auto-generated by `/config-bootstrap` — see the rejected-alternative in design.md.
- New helper: `av_resolve_template` in `shared/lib.sh` with a 2-layer resolver — project overrides → core defaults — using the existing `av_anvil_root()` function and `ANVIL_ROOT` env var. Preset layer deferred until an actual preset use-case appears.
- Mechanical: `dispatch-slice` writes the assembled agent prompt to `.anvil/dispatched-prompts/<slice-id>.prompt.md` before invoking the Agent tool. Makes the brief grep-testable; load-bearing for S1's acceptance criteria.
- New plan field: `checklist:` per slice in `tasks.md`, consumed by `/pre-merge-gate` at merge time. Slice lookup uses `.anvil/dispatched-agents.json` exact match (slice id → branch), not branch-prefix matching.
- New skill: `/analyze-plan` — v1 verifies cited file paths exist; v2 (deferred follow-up) extends to identifier and numeric-fact verification once the v1 false-positive rate is measured.
- Updates to existing skills: `dispatch-slice`, `spec`, `pre-merge-gate`, `grind`.
- Smoke tests under `tests/smoke/*.bats` for each new surface; runnable via `make -C tests smoke`.
- Documentation in `docs/` + CHANGELOG entry + ROADMAP tick.

### Out of scope

- Splitting anvil's plan into separate spec/plan/tasks artifacts (speckit's 3-file split). Anvil's audience is engineers; one plan document is fit-for-purpose.
- "No tech in spec" rule from speckit — wrong audience for anvil.
- Multi-agent emit (writing the same prompts into `.codex/`, `.gemini/`, etc.). Strategic but not urgent; this plan stays Claude-Code-shaped.
- **`/clarify` as a separate skill.** Adversarial review (self-review + hermes-ask, 2026-05-12) cross-confirmed that the operator-facing benefit is achievable as `--save-transcript` on `/spec` with zero new docs surface. Deferred to a follow-up issue: "Add `--save-transcript` flag to `/spec` that writes Q/A transcripts to `docs/plans/.transcripts/`." Reassess as a separate skill only if an operator explicitly asks for "interrogation mode without spec writing."
- Preset layer of the template resolver. Adopt 2-layer (project → core); promote to 3-layer when a real preset use-case appears.
- Identifier and numeric-fact verification in `/analyze-plan`. v1 scopes to file-path existence only — the verification with the highest signal-to-noise ratio. v2 follow-up will add identifier verification once we've measured v1's false-positive rate on real plans.
- Auto-generation of `.anvil/constitution.md` by `/config-bootstrap`. The synthesis would duplicate `dispatch-defaults.txt` content from the same source docs. Constitution is operator-authored or template-scaffolded; bootstrap is silent on it.
- A constitution-format version field.
- `/speckit.analyze`-style cross-artifact consistency between proposal.md and tasks.md. Out of scope; `/analyze-plan` only checks claims-vs-code.

- [ ] `/analyze-plan <plan-path>` flags a deliberately stale file path in a plan; passes a plan whose paths exist.
- [ ] All four surfaces have at least one smoke test under `tests/smoke/`, runnable via `make -C tests smoke`, and an entry in `CHANGELOG.md`.
- [ ] ROADMAP.md ticks the speckit-gold line.
